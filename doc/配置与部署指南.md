# scrcpy-web 配置与部署指南

> 更新日期:2026-09-15。适用范围:relay-server(云端 Node.js 服务)、scrcpy-console(Windows C 控制台)、
> Caddy 反向代理与域名、Google OAuth 登录、Cloudflare Worker 中继。
> 本文档不含任何真实密钥;所有密钥只存在于服务器 `relay-server/.env`(600 权限)与 Cloudflare 后台。

---

## 一、系统架构总览

```
浏览器 ──https://scrcpy.chuan.win(443, Caddy + Let's Encrypt 证书)
            │ 反向代理
            ▼
      relay-server (Node.js, pm2 守护)
        ├── 8443 HTTPS(Web 界面 + WebSocket,自签证书,Caddy 在前终止 TLS)
        ├── 8080 HTTP(Windows 控制台 / 本地 scrcpy 视频控制通道)
        │
        │ token 鉴权(仅控制台)
        ▼
Windows 控制台(scrcpy-console.exe,家里电脑)
        └── 本地中继 127.0.0.1:37183 起,桥接 scrcpy.exe ↔ 云端

登录:仅 Google OAuth(白名单 ADMIN_EMAIL 单账号)
Google token 交换:经 photo 项目的 Cloudflare Worker 中继(国内服务器连不上 googleapis)
```

| 组件 | 位置 | 管理方式 |
|------|------|----------|
| 服务器 | 腾讯云 `ssh ser2`(ubuntu@42.193.18.13) | pm2 + Caddy |
| 项目目录 | `/home/ubuntu/scrcpy-web` | git(服务器连不上 GitHub,用 bundle/rsync 同步,见第六节) |
| 进程 | `scrcpy-relay-server` | `pm2 restart ecosystem.config.js` |
| 反代 | `/etc/caddy/Caddyfile` | `sudo systemctl reload caddy` |

## 二、服务器端配置 `relay-server/.env`

所有密钥集中在 `relay-server/.env`(gitignore,不入库)。**必须 `chmod 600 .env`**。
加载逻辑:`lib/helpers.js` 的 `loadEnvFile` 在进程启动时读取,已存在的环境变量优先。

### 2.1 Google OAuth 登录(必需)

| 变量 | 说明 |
|------|------|
| `GOOGLE_CLIENT_ID` | OAuth 客户端 ID,与 photo 项目共用同一个客户端 |
| `GOOGLE_CLIENT_SECRET` | OAuth 客户端密钥(Google Cloud Console 获取) |
| `ADMIN_EMAIL` | 管理员白名单邮箱(单账号,严格比对;登录页拒绝时不泄露该地址) |
| `GOOGLE_REDIRECT_URI` | 可选。留空则按请求 Host 自动推导为 `https://<域名>/api/auth/google/callback` |

**Google Cloud Console 侧需要登记回调地址**( Authorized redirect URIs):

```
https://scrcpy.chuan.win/api/auth/google/callback
```

### 2.2 Google 中继(国内服务器必需)

服务器在国内,直连 `googleapis.com` 会失败(token 交换报 fetch failed)。浏览器侧授权仍走
Google 官方,仅服务器侧两个请求经 photo 项目的 Cloudflare Worker 中继:

| 变量 | 服务器上的值 |
|------|--------------|
| `GOOGLE_TOKEN_URL` | `https://chuan.win/api/scrcpy-auth-relay/token` |
| `GOOGLE_USERINFO_URL` | `https://chuan.win/api/scrcpy-auth-relay/userinfo` |
| `SCRCPY_RELAY_KEY` | 中继共享密钥,与 photo 项目 wrangler.jsonc 的 `SCRCPY_RELAY_KEY` vars **必须一致** |

> 本地开发(Mac)可直连 Google,**不要**在本地 .env 配这三项。
> 中继端点只转发这两个 Google 端点,`X-Relay-Key` 不匹配返回 403。

### 2.3 安全密钥(必需,泄漏即换)

| 变量 | 说明 | 生成方法 |
|------|------|----------|
| `CONSOLE_TOKEN` | 控制台连接令牌。**未设置时控制台 WebSocket 无法连接(fail closed)**。Windows 端须配置同一值(见第三节) | `openssl rand -hex 32` |
| `SESSION_SECRET` | 会话签名密钥。**不设置则每次重启全员掉线** | `openssl rand -hex 32` |

### 2.4 可选项

| 变量 | 默认 | 说明 |
|------|------|------|
| `ENABLE_HTTPS` | false | 生产为 true(见 ecosystem),加载 cert/ 下自签证书 |
| `PASSWORD_LOGIN` | true | 设 false 时仅允许 Google 登录(/api/login 返回 403,登录页隐藏密码表单) |
| `HTTP_PORT` / `HTTPS_PORT` | 8080 / 8443 | 监听端口 |
| `LOG_LEVEL` | INFO | ERROR/WARN/INFO/DEBUG |
| `ALLOWED_ORIGINS` | 空 | WS Origin 白名单(逗号分隔,跨域部署时用;默认仅同源) |
| `TURN_ENABLED` 等系列 | 未启用 | WebRTC TURN 中继(启用需开 3478 与 49152-65535 端口) |
| `WEBRTC_ENABLED` | true | WebRTC 数据通道开关 |

### 2.5 pm2 与 ecosystem.config.js

`ecosystem.config.js` 里的 `env` 块适合放**非密钥**配置(密钥一律走 .env):

```js
env: {
  NODE_ENV: 'production',
  ENABLE_HTTPS: 'true',
  PASSWORD_LOGIN: 'false',   // 仅 Google 登录
  HTTP_PORT: '8080',
  HTTPS_PORT: '8443',
  LOG_LEVEL: 'INFO'
}
```

常用命令:

```bash
pm2 restart ecosystem.config.js   # 重启(改了 env 需 delete+start 或 --update-env)
pm2 logs scrcpy-relay-server      # 看日志
pm2 save                          # 保存进程列表(开机自启已配置)
```

## 三、Windows 控制台配置

### 3.1 编译

```bat
:: Windows:双击 build.bat,或
build-mingw.sh            # macOS/Linux 交叉编译
build-mingw.sh webrtc     # 带 WebRTC 支持(需 vcpkg 的 libdatachannel)
```

构建已启用 `-fstack-protector-strong`。

### 3.2 运行与令牌

```bat
:: 方式一:环境变量(推荐,写进启动脚本)
set CONSOLE_TOKEN=<与服务器 .env 中 CONSOLE_TOKEN 相同的值>
scrcpy-console.exe 42.193.18.13:8080

:: 方式二:第二参数
scrcpy-console.exe 42.193.18.13:8080 <CONSOLE_TOKEN值>
```

**服务端已启用令牌校验,不带有效令牌的连接会被拒绝(1008)**。令牌通过 WS URL 的
`?type=console&token=...` 传输;服务器日志中令牌不落盘。

其他环境变量:`ADB`(adb 路径)、`VIDEO_PROFILE`(默认画质)、`TURN_HOST/USERNAME/CREDENTIAL`。

### 3.3 注意事项

- 程序退出时**只终止自己在册的 scrcpy 进程**(按 pid),不再全系统 taskkill,手工开的 scrcpy 不受影响;
- 本地中继只监听 `127.0.0.1`,但同机任意进程均可连接(已知边界,见审计报告 C-P1-4 待办);
- 修改设备别名的正确入口是 Web 页面(数据存服务器),控制台本地 `device_names.txt` 仅作历史遗留。

## 四、域名 / HTTPS(Caddy)

`/etc/caddy/Caddyfile`:

```
scrcpy.chuan.win {
    reverse_proxy https://127.0.0.1:8443 {
        transport http {
            tls_insecure_skip_verify
        }
    }
}
```

- 证书 Let's Encrypt 自动签发/续期;80 端口自动跳 HTTPS;WebSocket 自动透传;
- DNS:chuan.win 托管在 Cloudflare,`scrcpy` 子域 A 记录指向 `42.193.18.13`;
- 腾讯云安全组放行:22、80、443、8080、8443(及 RustDesk 21115-21119);
- 改完 Caddyfile 执行 `sudo systemctl reload caddy`。

## 五、登录与账号

- **仅 Google 登录**(`PASSWORD_LOGIN=false`),白名单为 `ADMIN_EMAIL` 单账号;
- Google 会话有效期 7 天;`SESSION_SECRET` 固定后重启不掉线;
- 登录页 `/login` 通过 `/api/auth/google/status` 判断按钮展示(该接口不限速);
- 认证相关接口(login / google 跳转 / 回调)有 per-IP 10 秒限速;
- 登录后设备改名/分组需 admin 角色(即白名单账号)。

## 六、更新部署流程(服务器连不上 GitHub)

```bash
# ---- 本机(Mac)----
git push origin main                        # 代码入库
git bundle create /tmp/deploy.bundle <服务器当前commit>..main
scp /tmp/deploy.bundle ser2:/tmp/

# ---- 服务器 ----
cd ~/scrcpy-web
cp relay-server/{auth-config.json,device_aliases.json,device_groups.json} /tmp/   # 备份运行时数据
git fetch /tmp/deploy.bundle main
git update-ref refs/remotes/origin/main FETCH_HEAD
git reset --hard FETCH_HEAD
cp /tmp/{auth-config.json,device_aliases.json,device_groups.json} relay-server/
pm2 restart scrcpy-relay-server
```

改动文件少时也可以直接 rsync 单个文件 + `git update-ref` 对齐。

**运行时数据(勿删,不在 git 里)**:
`auth-config.json`(登录账号,600)、`device_aliases.json`(设备别名)、`device_groups.json`(分组)。

## 七、常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 控制台连不上,服务器日志"控制台身份验证失败" | Windows 端 `CONSOLE_TOKEN` 与服务器不一致或未设置 |
| Google 登录报"回调处理失败: fetch failed" | 服务器 .env 缺 `GOOGLE_TOKEN_URL`/`GOOGLE_USERINFO_URL`/`SCRCPY_RELAY_KEY` 中继配置 |
| Google 报 redirect_uri_mismatch | Google Cloud Console 未登记 `https://scrcpy.chuan.win/api/auth/google/callback` |
| 重启后浏览器全部要求重新登录 | `SESSION_SECRET` 未固定(重新部署时别覆盖 .env) |
| 设备别名丢失 | 旧版纯 serial 键已兼容加载;若仍异常检查 device_aliases.json 是否被手动改坏 |
| 证书告警(直连 IP:8443) | 自签证书,日常请走 https://scrcpy.chuan.win |
| 匿名调用 /api/prepare-device-stream 返回 401 | 预期行为(2026-09-15 安全修复),带 token 或登录会话即可 |
